# YunSync V3 官方来源同步策略

生效日期：2026-09-29  
依据：`V3_MINI_PROGRAM_REDESIGN_PLAN.md` 的 M0 冻结项、M1 适配器边界以及 M5/M6 发布门槛。

## 结论

缺失信息按三类处理：

| 类型 | 处理方式 | 当前来源 |
|---|---|---|
| 运行时真实数据 | 通过适配器调用官方 API，页面不直接依赖供应商响应 | 和风天气 v1、香港天文台农历日期开放 API |
| 易变化的规则与元数据 | 定期检查官方页面并保存状态、时间和内容指纹 | 国家标准、微信隐私/定位、和风天气价格与缓存规则、法律法规 |
| 项目内部证据 | 只能由真实责任人或合同文件提供，禁止从互联网推断 | 主体身份、授权书、专业签名、测试逐人记录、正式服务凭据 |

机器可读登记表位于 `config/official-sources.json`。执行：

```powershell
node scripts/sync-official-sources.mjs
```

发布前严格校验：

```powershell
node scripts/sync-official-sources.mjs --strict
```

脚本输出：

- `official-source-sync/latest-report.json`：本次检查状态；
- `official-source-sync/attachments/external/web/<sha8>.md`：每个官方来源的摘要、时间、内容指纹和使用边界。

## 同步频率

- 天气：正式接入后按运行时请求，实时天气缓存 30 分钟、每日预报缓存 6 小时；
- 农历：M2 启用后按日期请求，年度节气/传统节日表在每年发布前复核；
- 价格、国家标准、微信隐私/定位：每月检查，并在每次提审或正式发布前强制检查；
- 法律法规：每季度检查，并在正式发布前强制检查；
- 所有来源发生内容指纹变化时：进入人工复核，不自动改变产品规则。

## 不能由官网自动补齐的内容

以下项目继续作为 M5/M6 发布硬门槛：

1. 小程序法定主体、统一社会信用代码和隐私联系人；
2. GB/T 46939—2025 标准文本及问卷产品化使用授权；
3. 营养、中医药、法规、安全和内容责任人的真实身份与签名；
4. 正式食谱逐条来源、授权和专业审核签字；
5. 5 人测试逐人记录与安全误解记录；
6. 和风天气正式账号凭据、合同或服务协议。

官网公开信息只能证明“规则和接口当前是什么”，不能证明“本项目已经得到授权或完成签署”。

## 当前阶段约束

本同步机制只补齐来源管理和 M1 适配器前置依据，不代表进入 M2。M1 仍须先在微信开发者工具完成模拟器/真机交互验收；验收通过后才能接入农历、节气、节日和内容库。
