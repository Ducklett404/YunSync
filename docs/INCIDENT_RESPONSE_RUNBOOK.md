# YunSync V2 事故响应手册

## 1. 分级

| 级别 | 示例 | 初始目标 |
|---|---|---|
| P0 | 大范围敏感数据泄露、错误内容可能造成即时严重伤害 | 立即停流或停用并启动指挥 |
| P1 | 越权、安全门禁失效、核心服务大范围不可用 | 15 分钟内响应和止损 |
| P2 | 局部故障、持续慢请求、OCR/MaaS 大量失败 | 4 小时内定位与缓解 |
| P3 | 无安全影响的单点缺陷 | 纳入常规修复 |

## 2. 响应流程

1. **发现与登记**：记录时间、渠道、请求 ID、路由模板和影响范围；不在群聊或工单复制健康正文、令牌或云密钥。
2. **分级与指挥**：指定事故、技术、隐私/安全和业务负责人。
3. **止损**：撤销凭据、隔离对象、停用内容、限制流量或回滚镜像；保留只读证据。
4. **调查**：关联应用日志、云审计、数据库和对象访问记录，并记录取证人。
5. **恢复**：先隔离验证，再逐步恢复；检查健康、就绪、核心流程和告警。
6. **通知**：由获授权的客户、隐私和法务负责人决定通知对象与时间。
7. **复盘**：五个工作日内形成时间线、根因、影响、修复、预防项和负责人。

## 3. 场景与演练

- 凭据泄露：立即轮换和撤销旧值，检查使用日志后重新部署；
- 对象越权：关闭接口或策略，确认 OBS 私有权限和所有权检查；
- 错误专业内容：停用版本，暂停受影响方案自动修订，通知专业负责人；
- 数据库故障：保持写入关闭，在隔离环境验证备份后按批准恢复点恢复；
- 模型异常：关闭真实 AI 路径，返回明确失败或固定安全文本；
- 监控中断：用健康探针和云日志临时值守并修复采集链路。

每季度至少演练凭据轮换、内容停用和备份恢复。影响停止、修复验证、证据归档、通知决定和后续任务均有负责人后才能关闭事故。
