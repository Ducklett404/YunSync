## 1. 复查范围

本轮逐项对照开发计划中的核心旅程、数据质量、安全边界、异常恢复、发布门禁和真实测试准备度，检查后端 Controller、Service、Repository、Model、Schema、外部适配层，前端路由、会话状态、主要业务页面，以及 Alembic 迁移和自动化测试。

本轮不把真实云服务、真实用户、健康专业审核、正式身份或比赛官方材料伪装成代码完成项。

| 编号 | 级别 | 问题 | 修复与验证 |

| CR-001 | P1 | OCR 返回重复标准代码时，原实现可能按记录条数满足“至少 3 项指标”的门槛 | 入库前拒绝重复代码；增加 `report_id + code` 唯一索引；排序和实验前置条件均按不同代码计数；补充服务与数据库回归测试 |

## 3. 复查后保持原设计的边界

- Production 只发布 `professionally_approved` 模板；当前合成审核角色不能伪造专业通过状态。该限制与数据字典一致，待正式身份和专业审核流程接入后再开放。
- 报告、实验与源文件均继续以服务端会话和对象归属为准；导出接口没有接受客户端 `user_id`。
- OCR、MaaS、OBS、RDS、DCS、IAM、日志平台、HTTPS 和公网部署的真实验收状态没有改变。
- 真实测试者、专业签字、正式截图/视频/PPT 和官方提交格式仍保持未完成。

## 4. 尚待后续处理的工程项

- 计划书的测试策略要求后端核心业务覆盖率不低于 80%，但当前开发环境没有覆盖率插件，且本轮连接软件源失败；因此只能确认测试通过，不能声称覆盖率目标已被测量或达成。
- 前端目前以 TypeScript 类型检查、生产构建、浏览器烟测和后端 API 集成为主，尚未建立独立的组件级自动化测试套件。
- 计划书早期用户旅程提到“手动录入基础指标”，当前详细周计划和 P0 验收只实现了上传/OCR/逐项修正；若正式版本仍需要纯手工建档，应在功能解冻后作为独立需求实施。
- 过期与已吊销会话的后台清理、正式账号刷新机制及用户数据删除申请流程，应与真实身份、数据保留政策和云部署一起完成。
