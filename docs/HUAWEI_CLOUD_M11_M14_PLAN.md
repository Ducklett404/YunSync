# YunSync M11—M14 华为云赛题开发计划

更新日期：2026-10-05

状态：**计划已建立，开发待执行**

适用赛题：基于华为云产品打造 AI 创新应用

## 1. 目标

在保留 YunSync 现有节气、天气、地域、个人体感、食材匹配与安全过滤能力的基础上，补齐赛题要求的华为云 AI、云数据库、Redis、代码智能体、Skills、自动部署和公开演示证据链。

M11—M14 不改变现有产品安全边界：审核食谱库和确定性规则负责候选、禁忌过滤与排序；大模型只负责理解自然语言和基于已选结果组织说明，不自由生成食材剂量、疗效或医疗建议。

## 2. 目标架构

```text
微信小程序 / H5 演示页
        |
        | HTTPS
        v
API Gateway 或 ECS 上的 API 服务
        |-- RDS PostgreSQL：食谱、节气内容、版本、来源、审计
        |-- DCS Redis：天气缓存、推荐缓存、限流、幂等
        |-- 华为云 MaaS：自然语言结构化、受控推荐说明
        `-- 天气数据服务：服务端持有凭据并负责降级

H5 静态文件、图片与演示材料 -> OBS + 自定义域名
构建、测试、部署、健康检查 -> CodeArts Pipeline / Deploy
资源创建和应用部署 -> CodeArts Agent + 项目级 Skills
```

## 3. M11：赛题合规与 CodeArts 证据

### 3.1 目标

让评审能够验证项目真实使用了华为云码道 CodeArts 代码智能体，并在需求理解、代码生成、问题修复、项目构建和部署上线各环节产生可追溯证据。

### 3.2 开发任务

- 在华为云码道 CodeArts 中导入当前仓库并建立项目工作区。
- 创建项目级 `.codeartsdoer/agents/` 与 `.codeartsdoer/skills/`。
- 建立资源规划 Skill：输出 VPC、ECS、RDS、DCS、OBS、IAM 的创建计划。
- 建立应用验证 Skill：运行类型检查、M2—M6 验证、H5 和微信构建。
- 建立部署 Skill：生成部署计划、执行部署、健康检查和失败回滚。
- 使用 CodeArts 代码智能体实际完成至少一项需求实现、一次缺陷修复和一次部署任务。
- 将 CodeArts 对话、变更文件、提交、流水线和部署日志登记到证据文档。

### 3.3 交付物

- `.codeartsdoer/agents/yunsync-cloud-agent.md`
- `.codeartsdoer/skills/yunsync-cloud-plan/`
- `.codeartsdoer/skills/yunsync-validate/`
- `.codeartsdoer/skills/yunsync-deploy/`
- `docs/competition/CODEARTS_EVIDENCE.md`

### 3.4 验收条件

- CodeArts 能识别并调用三个项目级 Skill。
- 证据表覆盖需求理解、代码生成、构建、问题修复和部署五个环节。
- 每项证据包含日期、操作者、输入、输出、关联提交或日志和截图路径。
- 证据不得包含访问密钥、数据库密码、令牌或个人健康原文。

## 4. M12：华为云后端、RDS 与 DCS Redis

### 4.1 目标

把当前前端本地数据结构升级为可部署、可观测、可降级的华为云 API，同时保留离线演示能力。

### 4.2 开发任务

- 建立独立后端服务和 `/health` 健康检查。
- 建立食谱、节气内容、来源、版本与推荐审计的数据模型。
- 将正式内容读取迁移至 RDS PostgreSQL；DEMO 数据通过独立种子脚本写入并明确标记。
- 使用 DCS Redis 缓存天气和推荐结果，并实现缓存版本、TTL、穿透保护和接口限流。
- 将天气服务密钥保留在服务端，前端只调用无密钥 HTTPS API。
- 实现以下 API：
  - `GET /health`
  - `GET /v1/context/today`
  - `POST /v1/recommendations/today`
  - `POST /v1/recommendations/pantry`
  - `GET /v1/recipes/{id}`
- 为 RDS、DCS 和外部天气异常建立超时、降级和可观测日志。
- 通过 IAM 最小权限、VPC、安全组和部署变量管理访问凭据。

### 4.3 数据边界

- 默认不把用户完整健康描述写入 RDS。
- 前端或 MaaS 只产生受控标签；推荐审计保存规则版本、候选 ID 和命中原因。
- 云端同步用户档案前必须增加明确同意、撤回、导出与删除接口。
- 日志不得记录 MaaS API Key、数据库连接串、Redis 密码或完整用户输入。

### 4.4 验收条件

- API 能从 RDS 返回带版本和来源的食谱。
- 同一请求第二次命中 DCS 缓存，缓存失效后能够重建。
- RDS、DCS 或天气服务不可用时返回明确降级状态，不返回错误推荐。
- 仓库中不存在真实密钥；`.env.example` 只列变量名和非敏感示例。
- 后端单元/契约测试和现有小程序回归均通过。

## 5. M13：MaaS 受控 AI 能力

### 5.1 目标

让用户通过一句自然语言描述体感、食材、时间和偏好，同时保证最终食谱来自审核库，安全过滤始终由确定性规则执行。

### 5.2 处理流程

1. 用户输入自然语言。
2. MaaS 输出符合 JSON Schema 的结构化标签。
3. 服务端校验枚举、长度、数量和置信度，拒绝未知字段。
4. 安全规则处理过敏、禁忌、高风险症状和不支持人群。
5. RDS 查询审核食谱，天气、地域、节气与档案参与排序。
6. MaaS 仅依据最终食谱和结构化原因生成简短说明。
7. MaaS 超时、格式错误或限流时，自动切换到现有表单和规则说明。

### 5.3 开发任务

- 新增首页“一句话告诉云循”输入卡片。
- 设计输入和输出 JSON Schema。
- 接入 MaaS Chat API，并配置超时、重试、Redis 缓存和熔断。
- 建立提示词版本管理和输出审计。
- 建立对抗样例：越权医疗请求、提示词注入、虚构食材、过敏冲突和超长输入。
- 在结果页展示参与推荐的天气、地域、节气、体感和食材因素。
- 将 AI 生成内容标识为辅助说明，并保留来源食谱与版本。

### 5.4 验收条件

- 规定自然语言样例均能转换为合法结构化标签。
- 模型不能新增审核库之外的食谱、剂量或功效。
- 所有过敏和明确禁忌仍保持 100% 硬过滤。
- MaaS 不可用时核心推荐仍可完成。
- 页面可以解释“为什么推荐”和“使用了哪些条件”。

## 6. M14：一键部署、流水线与云上 Demo

### 6.1 目标

使用 CodeArts Agent、Skills、Pipeline 和 Deploy 完成从仓库到华为云在线 Demo 的可重复部署。

### 6.2 开发任务

- 使用资源 Skill 创建或关联 VPC、ECS、RDS、DCS Redis、OBS、IAM 与安全组。
- 使用应用部署 Skill 将后端部署到 ECS；若最终改用 FunctionGraph，须保留同等的自动部署和回滚证据。
- 使用 OBS 和自定义域名部署 H5 演示页及静态资源。
- 建立 CodeArts Pipeline：安装依赖、类型检查、M2—M6 验证、H5 构建、后端测试、部署、健康检查。
- 使用 CodeArts Deploy 管理测试和演示环境参数。
- 部署失败时停止发布并回滚到上一个健康版本。
- 输出资源清单、部署摘要、测试报告和销毁步骤。
- 录制从自然语言输入到推荐结果的完整演示视频。

### 6.3 关于 auto-deploy Skill

赛题提供的 `auto-deploy` Skill 可用于创建单台 ECS、上传源码、启动应用和验证健康状态。该 Skill 不创建 RDS、Redis 或 OBS，因此 M14 必须补充独立资源创建 Skill，或者先由资源 Skill 创建并将连接变量安全传入应用部署 Skill。

### 6.4 验收条件

- 评审可通过公网 HTTPS 地址打开 H5 Demo。
- Demo 可完成今日推荐、体感输入和现有食材匹配三条主流程。
- 流水线从指定 Git 提交构建，部署后自动验证 `/health`。
- RDS、DCS 和 MaaS 调用均有不泄密的日志或监控证据。
- 提供一键部署、故障回滚和资源销毁说明。
- GitHub 包含根 README、依赖环境、部署指导、使用文档、许可证、截图或视频链接。

## 7. 执行顺序与依赖

| 顺序 | 里程碑 | 前置输入 | 完成标志 |
|---|---|---|---|
| 1 | M11 | CodeArts 账号与项目空间 | Skills 可调用，证据表开始记录 |
| 2 | M12 | 华为云 Region、VPC/RDS/DCS 配额 | 云 API、RDS、Redis 联调通过 |

M11—M14 可以使用明确标识的 DEMO 内容完成赛题技术验收。48 道正式审核食谱、授权体质问卷、真实主体信息和真人封闭试用仍属于正式发布门槛，不能因云端 Demo 完成而视为已经满足。
