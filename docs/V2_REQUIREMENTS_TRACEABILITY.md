## 1. 待客户确认的产品基线

| 项目 | 基线候选 | 明确排除 |
|---|---|---|
| 首版人群 | 18 岁及以上成年人；孕哺、已知疾病、用药、肝肾情况或医生限制进入专业咨询 | 儿童；急症处置；诊断、治疗、调药 |
| 首版地区 | 中国大陆演示与本地验收；正式地区在发布前填写 | 未确认地区的正式健康内容发布 |
| P0 指标 | `V2_METRIC_CATALOG.md` 的 19 个数值指标 | 用单一数值推断诊断或危急值 |
| 输入 | PDF/PNG/JPEG 报告与手工录入 | 未经用户逐项核对即作为正式数据 |
| 输出形式 | 指标摘要、安全分流、后续 1–3 个目标、3–7 个食谱、周计划与采购清单 | 当前 M1–M3 不生成正式食养方案 |
| 业务边界 | 一般健康信息与经审核的食养内容候选 | 医疗服务、处方、疗效保证、自动处理高风险用户 |
| 数据边界 | 合成数据优先；真实样本须脱敏、授权、限定用途和保存期 | 将真实健康数据写入日志、测试夹具或公开仓库 |

## 3. 用户旅程与现有关键页面

1. `/start`：阅读授权说明并完成急性症状等安全初筛。
2. `/report`：上传或手工创建报告，查看原件定位，修正并逐项确认。
3. `/profile`：填写六类食养安全信息；所有“尚未回答”均阻断。
4. `/safety`：查看 C/B/资料缺失/规则待发布/A 层结果及下一步。
5. `/`：查看当前已确认报告和后续阶段状态。
6. `/admin/content`：审核角色搜索、校验、比较、审核、发布、停用和回滚知识条目。
7. `/care-plan`：查看已审核方案草案、食谱卡、周计划、采购和确认状态。
8. `/follow-up`：填写执行反馈与复查提醒，核对两份报告，查看修订记录和历史快照。

这些路由已形成可点击前端，不代表客户或专业人员已完成页面及内容验收。
