# V2 首版指标字典（技术草案）

当前指标字典版本：`v2-p0-draft-1`；单位投影版本：`v2-unit-draft-1`。此表对应开发计划书第 5.2 节的 P0 范围，供 OCR 结果对齐标准代码。年龄段、性别等分类字段属于健康档案，不作为数值指标入库。

| 组别 | 标准代码 | 标准名称 | 展示单位 |
|---|---|---|---|
| 基本信息 | `height`, `weight`, `bmi`, `waist_circumference` | 身高、体重、身体质量指数、腰围 | cm、kg、kg/m²、cm |
| 血压 | `systolic_bp`, `diastolic_bp` | 收缩压、舒张压 | mmHg |
| 血糖 | `fasting_glucose`, `hba1c` | 空腹血糖、糖化血红蛋白 | mmol/L、% |
| 血脂 | `total_cholesterol`, `triglyceride`, `ldl_c`, `hdl_c` | 总胆固醇、甘油三酯、低密度脂蛋白胆固醇、高密度脂蛋白胆固醇 | mmol/L |
| 尿酸 | `uric_acid` | 尿酸 | μmol/L |
| 肝功能 | `alt`, `ast`, `ggt` | 丙氨酸氨基转移酶、天门冬氨酸氨基转移酶、γ-谷氨酰转移酶 | U/L |
| 肾功能 | `creatinine`, `egfr`, `urea` | 肌酐、估算肾小球滤过率、尿素 | μmol/L、mL/min/1.73m²、mmol/L |

实现位置：`backend/app/services/metric_catalog.py`。已知代码或名称别名映射到同一标准代码；二者明确指向不同指标时停止自动入库。未知指标保留原名称和代码供人工核对。原文仍保存在 `raw_text`。

确认后的 P0 指标可额外得到**标准单位投影**，原值、原单位和原参考范围保持不变。投影在 API 读取时计算，不持久化，也不修改报告原始字段。当前仅支持以下数值换算：

| 指标 | 原单位 → 标准单位 | 换算 |
|---|---|---|
| 空腹血糖 | mg/dL → mmol/L | 原值 × 0.0555 |
| 总胆固醇、LDL-C、HDL-C | mg/dL → mmol/L | 原值 ÷ 38.67 |
| 甘油三酯 | mg/dL → mmol/L | 原值 ÷ 88.57 |

血糖系数依据 [NIDDK《Diabetes in America》换算附录](https://www.niddk.nih.gov/-/media/Files/Strategic-Plans/Diabetes-in-America-3rd-Edition/DIA_Conversions.pdf)；血脂系数依据 [美国 AHRQ 报告附录](https://www.ncbi.nlm.nih.gov/books/NBK83505/)。本项目未用这些换算值设置临床阈值。

`kg/m2`、`mmol/l` 等只涉及写法的单位别名可直接匹配标准单位。其他单位标为 `unsupported_unit`，名称与代码冲突标为 `identity_conflict`，非有限数值标为 `invalid_value`；这些情况阻止报告完成确认并提示修正。用户可在报告最终确认前修正已逐项确认的字段。`BUN`（血尿素氮）不合并到尿素；肌酐、尿酸、HbA1c 等其他数值换算仍待专业审核。未知指标保留原身份并标为 `outside_catalog`，不参与 P0 单位投影。
历史上已确认但按当前规则存在冲突的报告，只允许修正冲突字段；修正后报告返回待确认状态，需重新完成报告确认。

这一步只解决部分常见单位的技术对齐。检测方法、有效数字、原报告参考范围和跨机构可比性尚未核定，不能仅凭投影值绘制临床趋势、诊断或生成食养方案。

`GET /metrics/summary` 对最近 20 份已确认报告按明确的 P0 标准代码对齐，显示检查日期、机构、检测方法、原值、原单位和参考范围。最近两次记录只有在检查日期明确、检测方法填写且一致、参考范围填写且经文本规范化后一致、单位可投影、标准指标唯一时才计算算术差。缺少方法、方法变化、参考范围缺失或不同、未投影或同批次重复代码时不计算差值；机构或原单位变化会明确提示。参考范围规范化只统一空白和常见标点，不解释区间含义或换算区间。此预览不判断改善、恶化或食养效果。
