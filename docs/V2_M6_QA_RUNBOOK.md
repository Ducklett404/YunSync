# M6 界面验收执行手册

本文用于 QA 在获得专业审核内容后，见证“第一次报告—方案执行—第二次报告—新方案”的完整流程。只使用获批准的合成或脱敏数据，不在截图、缺陷单或文件名中保留姓名、证件号、手机号等身份信息。

## 1. 前置门禁

- M1–M3 的需求、目标人群、安全规则和审核职责已经签署。
- M4 至少有 3 个仍有效的专业审核食谱，以及这些食谱引用的食材、禁忌和证据来源；不得把仓库中的候审草稿发布为正式内容。
- 测试账号是 `participant`，已完成同意、筛查和六类食养安全档案；风险分流允许生成一般健康教育方案。
- 准备两份属于该账号、检查日期先后明确的批准合成或脱敏报告。每份报告均完成逐项确认、危急提示核对和整份确认。
- 浏览器开发者工具无未处理错误，测试环境数据库已备份或可重建。

## 2. 主流程 M6-E2E-01

| 步骤 | 操作 | 预期结果 | 证据编号 |
|---|---|---|---|
| 1 | 登录参与者账号，打开第一份报告 | 报告属于本人，指标和原文定位均可核对，整份状态为已确认 |  |
| 2 | 打开“食养方案”，选择 1–3 项已确认指标并生成草案 | 仅引用已发布内容；显示目标、食谱版本、克数、步骤、频次、替代、禁忌、来源、7 天安排和采购清单 |  |
| 3 | 确认方案 | 状态变为 `ACTIVE`，版本为 1 |  |
| 4 | 在“执行与复查”记录已完成、已跳过和自行替换 | 每天只有一条记录；重复保存同一内容不新增记录；替换内容明确标为用户事实记录 |  |
| 5 | 设置复查日期和依据 | 日期来自医生、报告或既定个人计划；页面不生成医学复查周期 |  |
| 6 | 上传第二份报告并完成逐项及整份确认 | 第一版方案自动变为 `PAUSED`，原因为新报告；旧快照仍可查看 |  |
| 7 | 指定两份报告并执行对比 | 显示原值、单位、检查间隔和可比性；只有满足门禁的指标显示算术差；无改善、恶化或食谱疗效结论 |  |
| 8 | 选择第二份报告中的目标并生成新草案 | 新草案状态为 `READY`、版本为 2；显示旧方案执行摘要及目标、食谱和周频次变更 |  |
| 9 | 确认第二版方案 | 第二版变为 `ACTIVE`；第一版变为只读 `SUPERSEDED`；两版报告和内容版本引用保持不变 |  |
| 10 | 刷新、退出并重新登录 | 当前版本、执行记录、提醒、报告对比、变更日志和历史快照仍可读取 |  |

## 3. 安全分支 M6-SAFE-01

使用独立账号或重建测试数据，避免影响主流程证据。

| 步骤 | 操作 | 预期结果 | 证据编号 |
|---|---|---|---|
| 1 | 激活第一版方案并在当天记录“不适” | 当次记录保存，方案立即变为 `PAUSED`，页面提示停止执行并寻求专业评估 |  |
| 2 | 尝试填写后续日期或撤销不适 | 系统拒绝继续执行或自行撤销不适 |  |
| 3 | 上传并确认第二份报告后尝试自动修订 | 系统拒绝自动生成新方案，要求先完成专业评估 |  |
| 4 | 以另一参与者账号读取该方案、日志、修订或两份报告对比 | 均返回无权访问或资源不存在，不泄露对象是否存在 |  |

## 4. 可比性分支 M6-COMP-01

分别准备方法变化、参考范围变化、机构变化、单位不可转换、检查日期倒序和指标仅见于一份报告的案例。

- 方法、单位等关键条件不满足时不得显示算术差。
- 参考范围或机构变化必须给出限制提示。
- 检查日期倒序必须返回明确业务冲突，不得出现服务器错误。
- 一份报告缺失该指标时只展示单份记录，不得补值或推断趋势。

## 5. 截图与缺陷记录

建议证据文件名使用 `M6-案例编号-步骤-日期.png`。至少保存：第一版活动方案、三类执行记录、新报告导致的暂停、两报告对比、第二版变更日志、两版历史快照、不适暂停以及越权结果。

缺陷至少记录：案例编号、步骤、构建提交、实际结果、预期结果、复现率、严重级别、截图或日志位置、处理结论。任何 P0/P1 缺陷未关闭时不得签署 M6。

## 6. 签署回填

完成执行后，将证据目录和缺陷结论回填到 `V2_M6_ACCEPTANCE.md`。临床营养、中医药内容、QA、客户和项目负责人应分别填写本人姓名、组织、结论和日期；开发人员不得代签。
