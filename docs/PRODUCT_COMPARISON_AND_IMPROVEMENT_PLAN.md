# 云循竞品对比与改进计划

更新于 2026-11-25。范围为云循 V3 小程序与 H5 的「今日推荐」和「手头食材」流程。竞品信息来自公开产品说明，云循现状来自当前代码、开发计划与验收记录。

三项首版功能已落地。食材页支持本机常备食材和复制缺料，详情页支持逐步跟做。山药小米粥、番茄豆腐汤和清炒时蔬已补充示例提示。本轮使用 DEMO 食谱进行工程自测，正式材料与真人验收按项目决定暂缓。

## 三个成熟产品的可借鉴做法

| 产品 | 对方的做法 | 云循的第一版 |
| --- | --- | --- |
| **SuperCook** | 用户维护可随时增加或删除的食材库存，应用据此更新可做菜谱。 [开发者产品说明](https://apps.apple.com/us/app/supercook-recipe-by-ingredient/id1477747816) | 在食材页提供「保存为常备食材」。再次打开时预填，用户直接增删当天食材。沿用现有同义词去重、15 项匹配上限和过敏过滤，在本机数据导出和删除流程中纳入该清单。 |
| **Tandoor Recipes** | 将菜谱或餐单里的食材转换为可用或可导出的购物清单。 [购物清单文档](https://docs.tandoor.dev/features/shopping/) | 给有缺料的结果卡加「复制需购买材料」。清单根据当前匹配结果和份数生成，排除已有材料及已登记的替代项。只在用量能从源食谱可靠换算时显示数量。 |
| **美食杰** | 用图文和视频呈现细分烹饪步骤，帮助用户照着做。 [产品官网](https://j.meishi.cc/) · [开发者产品说明](https://apps.apple.com/cn/app/id399423833) | 详情页可逐步跟做，三道样例提供参考时长或可观察的完成状态。沿用「步骤不清楚」「制作太复杂」反馈，后续按食谱版本记录走查时发现的卡点。 |

## 走查任务与完成标准

### 1. 完成板端演示与首轮走查

- 用同一版本做三段演示。正常推荐并打开对应版本的详情，修改过敏档案后重新匹配，模拟 API 断连后查看本机的同版本副本。额外检查 2027 年春节和一项普通日期。记录板卡型号、Git 提交、操作结果和请求记录。
- 让 3–5 位用户在手机上独立完成「找到今日推荐及做法」和「按已有食材找到可做的菜」。记录成功数、总次数、用时、食材输入次数和失败原因，填入 M6 记录。后续封闭试用沿用 V3 指标：返回用户 3 秒内看到主推荐，首次用户 90 秒内完成设置并看到推荐，两项核心任务完成率至少 90%。 [V3 成功指标](../V3_MINI_PROGRAM_REDESIGN_PLAN.md) · [M6 试用记录](M6_TRIAL_RESULTS.json)

### 2. 验证常备食材是否节省录入

- 在现有「食材」页增加显式的本机保存入口。再次打开时预填常备食材，当次输入仍可编辑。修改条件继续立即使旧结果与进行中的请求失效。
- 让同一批用户用相同场景各完成一次初次录入和一次复访匹配，比较需要手动录入的食材数和任务用时。功能验收覆盖重启保留、同义词去重、清空和导出，以及预填食材命中过敏规则时的拦截。

### 3. 验证缺料清单和跟做步骤是否可用

- 验证可复制的单道食谱清单，覆盖完全匹配、登记替代、缺 1–2 种、切换份数和改条件五种情况。用户应能正确指出需要购买的材料。
- 用三道样例观察用户如何跟做。记录首次尝试的卡点及改版后的复测结果，核对步骤、来源和版本一同更新。

准备正式发布时，沿用 M6 的内容签署和真机门禁。每次换年先核对下一年的农历、节气与节庆包日期，再以同一数据版本验证小程序离线和板端 API。 [M6 发布与回滚](M6_RELEASE_AND_ROLLBACK.md)
