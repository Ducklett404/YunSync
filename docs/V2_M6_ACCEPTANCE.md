## 工程交付

- [x] 7 天安排按日记录完成、跳过、自行替换、不适及备注；同日重复请求幂等，未来日期拒绝提前填写。
- [x] 不适记录即时将活动方案转为 `PAUSED`，保留日志，阻止自动恢复和自动修订；不适内容不写入审计载荷。
- [x] 用户自行填写复查日期与医生/报告/既定计划依据；只在应用内显示到期状态，不擅自推断医学复查周期。
- [x] 两份本人已确认报告按标准指标对齐，显示检查间隔、原始值、单位、保守算术差及参考范围/方法/机构等可比性提示；不输出改善、恶化或食谱疗效结论。
- [x] 新报告触发活动方案暂停；重新执行安全与内容门禁后生成 `READY` 新版本。新旧方案快照、修订对比及变更日志持久化；用户确认后旧版变为只读 `SUPERSEDED`。
- [x] 参与者接口限制本人数据；旧报告未确认、无新报告、风险拦截、候选内容不足及不适记录均返回明确业务冲突。

## 本地验证

- `tests/test_care_plan_service.py`：合成两报告闭环、反馈幂等与不适暂停、审计最小化、用户设定提醒、不可比报告停算、检查日期倒序业务冲突、版本迁移与越权拒绝。
- 后端全量回归：`python -m pytest -q`。
- 前端：`npm run typecheck`、`npm run build`。
- 数据迁移：临时 SQLite 空库 `upgrade head → downgrade -1 → upgrade head`；含两个旧方案的副本验证版本号回填、用户与版本联合唯一索引，以及 `SUPERSEDED` 回退为 `PAUSED`。

上述报告、指标、审核角色与食谱均为**合成工程夹具**。现有食谱种子仍是未发布草稿，正式参与者环境不能自动走通方案生成，更不能据此宣称对任何人有医学适用性。
