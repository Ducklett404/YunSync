## 测试前

- 记录构建提交、数据模式、食谱版本、测试日期、设备/系统和网络情况。
- 使用匿名编号，不收集参与者真实健康资料；测试过敏条件采用指定场景数据。
- 提示食谱仍为演示数据，反馈只保存在测试设备；不要将测试理解为健康或治疗服务。
- 主持人提供任务描述，不提示点击路径，记录成功/失败、用时、困惑和原话。

## 任务

| 任务 | 描述 | 观察与完成标准 |
|---|---|---|
| 今日任务 | 找到今天主推荐并进入做法 | 记录是否完成、秒数、是否读懂推荐原因 |
| 食材任务 | 输入番茄、豆腐、食用油并找到结果 | 记录是否完成、秒数；区分已有与需再买材料 |
| 收藏与反馈 | 收藏一道食谱，重启后从“我的”找回并选择反馈 | 确认持久化、反馈选中、记录仅本机保存的理解 |
| 安全场景 | 按指定场景填写大豆过敏，再尝试匹配豆腐 | 冲突食谱必须排除；返回食材页不保留旧结果 |
| 天气与权限 | 拒绝定位，手动选城市；天气不可用 | 可继续浏览，不误把演示/缺失天气当作实时数据 |
| 清除记录 | 取消一次清除，再确认清除 | 取消保留记录，确认清除收藏/浏览/反馈，档案保留 |

核心任务完成率 = 今日与食材任务成功次数 / 两项任务总次数。分别记录走查和封闭试用，要求不低于 90%。不能用自动测试通过率替代真实用户完成率。

## 结果记录

将实际结果填写到 `M6_TRIAL_RESULTS.json`。每位参与者结构如下（仅字段说明，不能直接当作已执行记录）：

```text
id: 匿名编号，例如 P01
medicalMisunderstanding: 是否出现医疗误解，必须记录实际观察
allergenExclusionConfirmed: 是否确认指定过敏场景被排除
tasks.today / tasks.pantry: { completed: 实际成功与否, seconds: 实测用时 }
```

缺陷记录 `id/priority/status/evidence`；设备检查记录 `id/status/evidence`；签署记录 `role/name/date/status/evidence`。证据引用项目内记录或受控资料，不在仓库放个人健康信息。

执行 `npm run check:m6` 可核对记录完整性、人数、完成率、未关闭 P0/P1、兼容证据及五类签署。当前空记录应失败。自动核对不能证明证据真实性，发布负责人仍需核验。

五类签署：专业内容、安全、隐私、真实用户验收、发布负责人；AI 不代签。
