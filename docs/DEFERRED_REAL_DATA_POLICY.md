# YunSync V3 · 延迟绑定真实数据策略

生效日期：2026-09-29  
决策来源：项目所有者明确要求“最终使用真实数据，但当前不确定具体主体、供应商授权和签署人”。

## 决策

M1—M4 允许在 `DEMO_MODE` 下使用明确标识的演示数据推进工程实现；真实数据来源、法定主体、授权证明和专业签署继续作为 M5/M6 的硬性发布门槛。

这是一项受控计划调整：不把演示数据冒充真实数据，不把虚拟签署当作 M0 正式验收证据，也不降低计划书的最终发布标准。

## 开发数据可以虚拟的范围

- 固定天气快照；
- 演示城市与节气日期；
- 标注为 `demo` 的食谱和审核记录；
- 测试 AppID、测试主体名称和测试隐私联系人；
- 未登录用户的本地演示档案；
- API 的加载、空状态、错误和降级响应。

## 不得虚拟的发布证据

- 5 人测试的真实结果；
- 专业审核人的真实身份与签署；
- 正式食谱的来源、授权和审核状态；
- 小程序法定主体与隐私联系人；
- GB/T 46939—2025 问卷使用授权；
- 真实天气服务凭据与正式服务协议；
- 过敏、高风险症状和特殊人群拦截的测试结果。

## 工程约束

1. 所有外部数据通过适配器接口接入，页面不得直接依赖供应商响应结构。
2. 每份数据包含 `source`、`isDemo`、`version`、`reviewStatus` 和 `updatedAt` 等溯源字段。
3. 演示数据必须在界面或开发标识中明确显示“演示”。
4. 生产构建检测到 `isDemo=true`、虚拟签署、未审核食谱或测试主体时必须失败。
5. 真实数据接入只替换适配器和配置，不重写页面和业务规则。
6. 正式发布仍须完成原计划 M5/M6 的内容、安全、隐私、真实用户和发布负责人共同签署。

## 当前阶段

- M0 产品范围与技术边界按计划书冻结；外部真实主体和签署信息延迟绑定。
- 允许开始 M1 的无登录演示数据实现。
- 不允许把当前状态标记为“可正式发布”。
- 可公开确认的缺失信息改由 `config/official-sources.json` 登记，并通过 `scripts/sync-official-sources.mjs` 从官方网站校验；来源变化不会自动改写产品规则，而是触发人工复核。
- 官网同步不能替代法定主体、服务凭据、合同/授权书、专业签名和真实测试记录，这些仍是 M5/M6 硬门槛。
