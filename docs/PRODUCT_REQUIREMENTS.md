# YunSync 云循产品需求基线

> 版本：V0.5（第 6 周实验状态机与锁定日程基线）
>
> 日期：2026-09-11
>
> 数据口径：仅使用合成数据或明确脱敏的演示材料
>
> 审核状态：产品与技术基线已形成；健康文案与行动模板仍待专业指导老师确认

## 1. 产品目标

云循帮助关注体重与代谢健康的成年人，把已确认的健康信息转化为一项低风险、可记录、可复盘的 14 天个人微实验。平台只提供健康教育、自我监测和生活方式支持，不诊断疾病、不提供治疗或药物调整意见。

首个参赛版本的成功标准：用户可以在不依赖口头指导的情况下完成“知情与初筛 → 报告确认 → 候选行动 → 14 天计划 → 每日记录 → 结果评估”主流程，并理解结果仅是个人短期观察。

## 2. 用户与使用情境

| 用户 | 核心任务 | 当前版本支持 |
|---|---|---|
| 健康管理用户 | 找到更容易坚持、可观察的生活方式行动 | 完整演示主流程 |
| 健康管理指导者 | 复核安全边界、行动模板与结果措辞 | 审核角色可读取最小化审计事件并管理原型模板版本；真实专业复核待完成 |
| 竞赛评委 | 在 5 分钟内核查创新机制、云能力与安全性 | 合成案例、可审计日程与结果 |

## 3. 范围

### 3.1 本阶段必须覆盖

- 知情说明、演示数据声明与安全初筛；
- 演示账号短期会话、版本化授权、撤回与角色权限；
- 合成健康目标、作息、限制条件和记录偏好档案；
- 受控报告上传、带置信度与原文位置的合成 OCR 结果、逐字段确认和修正；
- 三个来自模板库的候选行动及排序理由；
- 后端生成且不可由前端篡改的 14 天 7:7 随机日程；
- 按行动类型填写正确主要指标；
- 显示有效观测、完成率、观察差异与局限；
- 所有关键页面的加载、空、错误、成功或拦截状态。

### 3.2 本阶段不做

- 真实身份认证、真实健康档案或真实报告存储；演示账号与合成档案不代表正式账号体系；
- 疾病诊断、治疗方案、处方或药物剂量调整；
- 未经健康专业审核的自定义行动或强度；
- 用短期个人结果证明长期疾病疗效；
- 真实华为云资源接入、收费服务或真实用户招募。

## 4. 用户故事与验收标准

### US-01 知情说明与安全初筛

作为首次使用者，我希望先理解产品边界并完成安全初筛，以便知道当前流程是否适合继续。

- AC-01.1：未勾选全部知情项时，“继续”按钮不可用。
- AC-01.2：任一安全问题回答“是”时，页面显示停止提示且不能继续。
- AC-01.3：答案保存到合成演示档案，刷新后可恢复；不得写入真实身份或健康数据。
- AC-01.4：页面明确说明“不诊断、不治疗、不调药”和“仅使用合成或脱敏材料”。

### US-02 报告上传与识别

作为用户，我希望上传 PDF 或图片并查看结构化候选指标，以便减少手工录入。

- AC-02.1：只接受 PDF、PNG、JPEG，最大 5 MB；空文件、扩展名/MIME/文件签名不一致和超限文件被拒绝。
- AC-02.2：Mock 模式必须标记结果为合成，不得暗示已真实识别文件内容。
- AC-02.3：OCR 失败时不生成伪造指标，并提供可恢复的错误提示。

### US-03 指标确认

作为用户，我希望核对指标名称、数值、单位和参考范围，以便只让已确认信息进入后续流程。

- AC-03.1：未确认报告不能生成候选行动。
- AC-03.2：待确认、已确认和已修正状态可区分，修正不覆盖原始 OCR 文本与初始结构化值。
- AC-03.3：所有字段必须逐项确认或修正；低于 80% 的置信度使用额外视觉提示，不能批量跳过。

### US-04 候选行动比较

作为用户，我希望比较三个低风险行动的指标、依据和安全条件，以便只选择一项开始实验。

- AC-04.1：候选项均可追溯到代码、版本、审核范围和当前有效状态。
- AC-04.2：排序分数展示三项权重与得分贡献，并明确不是医学疗效概率。
- AC-04.3：高风险、报告未确认、确认字段少于 3 项、模板停用、非低风险或审核状态无效时返回空列表或明确拦截信息。
- AC-04.4：原型规则校验不得显示为专业审核；Production 只允许专业审核状态的模板。
- AC-04.5：受控解释必须通过长度、模板名称与诊断/调药/极端方案/疗效承诺校验，失败时使用标记来源的固定解释。

### US-05 生成 14 天计划

作为用户，我希望系统生成固定日程，以便按提醒日和常规日做个人内比较。

- AC-05.1：每轮恰好 14 天，包含 7 个提醒日和 7 个常规日。
- AC-05.2：同一种子生成相同日程，种子与日程可审计。
- AC-05.3：同一用户新建实验时，既有活动实验转为暂停；数据库保证同一用户最多一个 `active` 实验。
- AC-05.4：开始时保存日程版本、随机种子、完整日程、锁定时间和摘要；日期、顺序、分组或摘要不一致时停止操作。
- AC-05.5：只允许 `active → paused/terminated/completed`、`paused → active/terminated/completed`；终止和完成均为不可恢复的终态。
- AC-05.6：只有到达第 14 天且 14 个日期均已有记录时才允许完成实验。

### US-06 每日记录

作为用户，我希望在 60 秒内记录完成情况、主要指标和少量干扰因素。

- AC-06.1：未来日期、周期外日期和伪造分组被后端拒绝。
- AC-06.2：同一实验同一日期重复提交执行更新，不产生重复记录。
- AC-06.3：饭后活动、饮料替换、进食顺序分别使用对应主要指标。
- AC-06.4：未完成或缺失记录不自动补零。

### US-07 结果理解

作为用户，我希望同时看到差异、数据量和限制，以便不过度解读结果。

- AC-07.1：提醒日或常规日任一组少于 2 个有效观测时，不给出方向性结论。
- AC-07.2：页面显示主要指标、两组均值、差异、完成率和有效观测数。
- AC-07.3：结果文案明确不能推断疾病疗效，也不能直接推广到其他人。

### US-08 异常恢复

作为用户，我希望在网络或外部服务失败时看到清晰提示，以便重试或使用降级流程。

- AC-08.1：加载、空数据、接口错误与成功状态使用不同反馈。
- AC-08.2：OCR 或大模型不可用时，核心演示可切换到明确标记的 Mock 模式。
- AC-08.3：重复点击提交不会创建重复业务记录。

### US-09 演示身份与角色

作为演示参与者，我希望使用不采集真实身份的演示账号进入系统，以便验证受保护流程。

- AC-09.1：未登录请求健康接口返回 401；用户身份只从服务端会话确定。
- AC-09.2：数据库只保存会话令牌摘要，注销、过期或吊销后令牌不可继续使用。
- AC-09.3：参与者不能读取审计列表，审核角色不能读取参与者健康工作区。
- AC-09.4：Production 启动时若演示登录开启则拒绝启动。

### US-10 版本化授权与撤回

作为参与者，我希望知道接受了哪个版本并可随时撤回，以便控制新的健康数据处理。

- AC-10.1：系统只接受当前知情说明版本，每名用户最多一条活动授权。
- AC-10.2：没有活动授权时健康接口返回 403。
- AC-10.3：撤回后立即阻止新的报告分析，并暂停活动实验。
- AC-10.4：接受与撤回均记录不含健康正文的审计事件。

### US-11 合成健康档案

作为参与者，我希望保存合成目标、作息、活动基础、限制和偏好，以便验证个性化流程。

- AC-11.1：档案字段有长度与枚举校验，不采集精确出生日期。
- AC-11.2：高风险初筛任一项触发后，候选行动和新实验均被后端拒绝。
- AC-11.3：档案审计只记录变更字段名，不记录字段内容或初筛答案。

## 5. 异常流程

| 编号 | 触发条件 | 系统行为 | 用户下一步 |
|---|---|---|---|
| EX-01 | 未同意知情说明 | 禁用继续按钮 | 完成全部确认或退出 |
| EX-02 | 安全初筛任一项为“是” | 停止自助实验流程 | 先寻求专业人员评估 |
| EX-03 | 上传空文件、错误格式或超过 5 MB | 拒绝请求，不创建报告 | 重新选择合规演示文件 |
| EX-04 | OCR 超时或失败 | 不返回伪造指标 | 重试或切换 Mock 演示 |
| EX-05 | 报告未确认 | 候选行动为空，禁止建实验 | 返回报告页确认 |
| EX-06 | 高风险标记或模板非低风险 | 禁止创建实验 | 显示安全边界 |
| EX-07 | 未来、越界日期或伪造分组 | 拒绝保存 | 使用日历中的可记录日期 |
| EX-08 | 重复日期 | 更新原记录 | 显示保存成功 |
| EX-09 | 两组任一少于 2 个有效值 | 仅报告数据不足 | 继续记录或延长观察 |
| EX-10 | 页面刷新或弱网 | 保持后端事实，不篡改随机分组 | 重新加载后继续 |
| EX-11 | 未登录、会话过期或已注销 | 返回 401，不处理健康数据 | 重新登录演示账号 |
| EX-12 | 未授权、授权过期或已撤回 | 返回 403，停止新的健康处理 | 阅读当前说明并重新授权 |
| EX-13 | 角色越权或访问他人对象 | 返回 403 或不泄露存在性的 404 | 返回角色允许的页面 |

## 6. 非功能要求

- NFR-01 可访问性：表单控件有可读标签，关键状态不仅依赖颜色表达，键盘可完成主流程。
- NFR-02 响应式：320 px 宽度下无页面级横向溢出；主要按钮触控区域不小于 40 px。
- NFR-03 安全：密钥只通过环境变量或密钥服务注入，仓库不得包含真实凭据和个人健康数据；鉴权与对象归属必须由后端执行。
- NFR-04 可审计：报告来源、用户确认、行动版本、随机种子、保存事件和结果口径可追踪。
- NFR-05 可降级：外部 AI、OCR 或缓存不可用时给出明确状态，核心 Mock 演示仍可运行。
- NFR-06 性能：非 AI API 的最终目标 P95 小于 500 ms；本阶段以构建通过和主流程冒烟为门禁。

## 8. 外部确认项

以下事项不能由开发过程代替，保持未完成状态：

- 健康专业指导老师审核安全问题、行动模板和结果措辞；
- 3 至 5 名目标用户完成可用性走查并记录真实耗时；
- 比赛最终提交格式、截止日期、华为云服务权限和配额核对；
- 团队角色、负责人和实际周历确认。
